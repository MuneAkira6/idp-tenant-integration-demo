# テンプレート：事実表の 1 件

## 目的

外部のシステムについて観察したことを、日付・測ったコマンド・その出力の三つ組みで残します。あとから誰でも同じことを測り直せる形にするためです。

## 使い方

1. 1 件につき 1 つの事実だけを書きます。二つ書きたくなったら 2 件に分けます。
2. 測ったコマンドは、そのまま貼り付けて再実行できる形で書きます。資格情報は環境変数の名前だけを書き、値は書きません。
3. 出力は原文を貼ります。長い場合は、結論に関わる部分を省略なしで貼り、省いた範囲を書き添えます。
4. その事実に依存する判断をする前に、もう一度測ります。測り直したら「最後に測り直した日」を更新します。
5. 結論が覆ったら、元の記述を消さずに「置き換え済み」の枠を足し、新しい観察をその下に書きます。
6. 自分たちの資格情報でその経路が通らなかった場合も、事実として 1 件書きます。

## 記入する本体

（以下の見出しの階層は、貼り付け先の文書に合わせて上げてください。）

### F{{番号}}：{{一行の事実}}

- 測った日：{{YYYY-MM-DD}} ／ 最後に測り直した日：{{YYYY-MM-DD}}
- 測った人：{{担当}}
- 測ったコマンド：`{{コマンド}}`
- 出力：

```
{{出力の原文}}
```

- そこから言えること：{{結論を 1〜2 文で}}
- この事実に依存している判断：{{判断の ID}}

置き換え済み（覆されたときだけ足します）

- 置き換えた日：{{YYYY-MM-DD}}
- 新しい観察：{{原文}}
- 元の記述をどう扱うか：残します。上の記述は当時の観察として読んでください。

## 記入例（Acme Tasks）

### F12：IdP のグループ応答は 1 ページで返り切らない

- 測った日：2026-09-24 ／ 最後に測り直した日：2026-09-29
- 測った人：テナント基盤担当
- 測ったコマンド：`curl -s -H "Authorization: Bearer $IDP_TOKEN" "$IDP_BASE/groups?limit=200"`
- 出力：

```
{"items":[ ... ],"next":"cursor:eyJvZmZzZXQiOjIwMH0"}
```

- そこから言えること：`next` が返るので、1 回の呼び出しでは全件を取得できません。取得処理は続きの取得に対応する必要があります。
- この事実に依存している判断：D3（グループ取得の実装方針）

### F13：監査 API は自分たちの資格情報では通らない

- 測った日：2026-09-26 ／ 最後に測り直した日：2026-09-26
- 測った人：テナント基盤担当
- 測ったコマンド：`curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $IDP_TOKEN" "$IDP_BASE/audit/events"`
- 出力：

```
403
```

- そこから言えること：監査イベントは存在しますが、いまの資格情報では読めません。読める前提で設計すると、実装の終盤で詰まります。権限の付与を依頼するか、監査は範囲外にするかを先に裁定します。
- この事実に依存している判断：D4（監査ログの取得元）

置き換え済み

- 置き換えた日：2026-09-29
- 新しい観察：権限付与後に同じコマンドで `200`。応答は仕様書に載っていない項目も含んでいました。
- 元の記述をどう扱うか：残します。上の `403` は当時の観察として読んでください。
