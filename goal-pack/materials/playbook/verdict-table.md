# テンプレート：判定表

## 目的

項目ごとに判定と証拠を並べ、どこまで確かめたかを解釈の余地なく示します。文章で進捗を書く代わりに、1 行 1 項目で残すための表です。

## 使い方

1. 判定は PASS / FAIL / BLOCKED / DEFERRED の四つから選びます。
2. PASS の証拠には、観察した出力の原文を貼ります。要約や「通りました」は証拠になりません。
3. FAIL は「期待 X / 実際 Y」と書けるときだけ使います。書けないなら FAIL ではありません。
4. 環境で前提を作れない項目は BLOCKED にします。手で直した環境で通ったものも、ここに入れます。
5. 未裁定の事項に依存する項目は DEFERRED にし、どの裁定を待っているかを書きます。
6. 条件つきで通った項目は、PASS のまま注記を添えます。注記のない PASS と見分けが付くようにします。
7. 一つの項目で片方の経路しか確かめられないときは、複合判定にして両方の判定を書きます。
8. 数えるときは、複合判定の 1 行をそれぞれの判定に 1 件ずつ数えます。行数と判定の件数は一致しなくなるので、内訳には行数と件数の両方を書きます。注記付きの PASS は、注記があっても PASS 1 件です。
9. 補助の語（N/A・INFO・INCONCLUSIVE・サーバー側で検証済み）は、四つの判定の代わりには使いません。補助の語を使った行も、内訳にその語で 1 件数えます。

## 記入する本体

### 判定表

対象：{{何の判定表か}} ／ 被テスト版：{{識別子または指紋}} ／ 判定日：{{YYYY-MM-DD}}

| # | 項目 | 判定 | 証拠 |
|---|---|---|---|
| 1 | {{確かめること}} | PASS / FAIL / BLOCKED / DEFERRED | {{観察した出力の原文}} |

内訳：{{n}} 行・判定 {{n}} 件（PASS {{n}}・FAIL {{n}}・BLOCKED {{n}}・DEFERRED {{n}}・補助の語 {{n}}） ／ 今回カバーしていないもの：{{範囲}}

## 記入例（Acme Tasks）

### 判定表

対象：IdP グループと役割の対応づけ ／ 被テスト版：`sha 4f1c9ab` ／ 判定日：2026-09-30

| # | 項目 | 判定 | 証拠 |
|---|---|---|---|
| 1 | 対応づけたユーザーが再サインインで設定画面を開ける | PASS | 設定画面が開き、右上に「テナント管理者」と表示 |
| 2 | 対応づけを外すと設定 API が拒否する | PASS | `403 Forbidden`（応答本文 `{"error":"forbidden"}`） |
| 3 | 監査担当が変更履歴を閲覧できる | PASS（注記：閲覧は自テナント分のみ。横断閲覧は C4 として未裁定） | 監査画面に 2 件表示。他テナント分は 0 件 |
| 4 | 対応づけの反映 | 反映の経路は PASS ／ グループ名変更時の追従は BLOCKED | 反映：再サインインで役割が切り替わることを確認。追従：検証用テナントでグループ名を変更する権限がなく、前提を作れない |
| 5 | 手動付与と対応づけが衝突したときの優先順位 | DEFERRED | C2（優先順位）の裁定待ち |
| 6 | 画面側での権限判定の有無 | N/A | 画面側に判定を置かない設計のため、確かめる対象がない |

内訳：6 行・判定 7 件（PASS 4・FAIL 0・BLOCKED 1・DEFERRED 1・N/A 1）。4 番は複合判定なので、PASS と BLOCKED を 1 件ずつ数えています。3 番は注記付きですが PASS 1 件です。 ／ 今回カバーしていないもの：グループが多いテナントでの反映、監査ログの出力内容
